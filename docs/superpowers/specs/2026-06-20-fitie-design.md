# Fitie — 설계 문서 (Design Spec)

- **날짜:** 2026-06-20
- **플랫폼:** iOS (SwiftUI), 아이폰 전용
- **상태:** 설계 승인됨 → 구현 계획(plan) 작성 예정

---

## 한 줄 포지셔닝

> 손으로 체크하지 않아도 **HealthKit이 알아서 채워주는 정직한 습관 트래커** —
> 그리고 그 습관이 내 **컨디션**을 어떻게 바꾸는지 온디바이스 AI가 짚어주는 앱.

대부분의 습관 앱은 사용자가 직접 "완료"를 누른다. Fitie는 실제 건강 데이터로
습관 완료를 **자동 판정**한다. 같은 데이터가 매일의 컨디션(기분·에너지)과 엮여
"어떤 습관이 내 컨디션을 좋게 하는가"라는 인사이트로 이어진다.

핵심: HealthKit이 공유 엔진이다. 그 데이터를 (1) 습관 자동 판정과 (2) 컨디션
상관 분석에 두 번 쓰기 때문에, 기능 수는 적은데 깊이가 있어 보인다.

---

## 목표 / 목적

- **App Store 출시 가능한** 완성도 + **포트폴리오**로 내세울 만한 품질
- iOS 네이티브 강점(HealthKit, Live Activity, 온디바이스 AI)을 제대로 보여주기
- 솔로 개발자가 작게 만들어도 "잘 만든 티"가 나는 좁고 명확한 제품

## 비목표 (Non-goals, v1)

- 소셜/공유/랭킹 기능 없음
- 계정/로그인/클라우드 동기화 없음 (전부 로컬, 온디바이스)
- 의학적 조언·진단 없음 (관찰형 인사이트만)
- 멀티 플랫폼(Watch/iPad/Mac) 없음 — v1은 아이폰 전용

## 제약 조건 (중요)

개발자는 **유료 Apple Developer Program 미가입**(무료 Personal Team)이며, 당장
출시 계획이 없다. 따라서 v1은 **시뮬레이터 타깃 우선**으로 개발한다.

| 항목 | 상태 | 대응 |
|---|---|---|
| App Store / TestFlight 배포 | ❌ 유료 필요 | v1 범위 밖 |
| 실기기 7일 만료 / 실기기 빌드 | ⚠️ 유료 필요 | 시뮬레이터로 개발 |
| **HealthKit** | 🟢 시뮬레이터에서 개발 가능 | Simulator Health 앱 샘플 데이터로 |
| **App Groups (홈 위젯 데이터 공유)** | 🔴 Personal Team에서 에러 | **홈 위젯 v1 제외**, 자리만 설계 |
| **Live Activity (ActivityKit, 로컬)** | 🟢 App Groups 불필요 | v1 포함 |
| **로컬 알림** | 🟢 가능 | v1 포함 |
| **Foundation Models (온디바이스 AI)** | 🟢 멤버십 무관 | v1 포함, 미가용 시 폴백 |

> 무료 계정 기준이라 **홈 화면 데이터 위젯만 v1에서 제외**한다. 나머지 핵심 기능은
> 모두 시뮬레이터에서 동작한다.

### 개발 초반 검증 스파이크 (코딩 시작 직후)

1. Personal Team에서 HealthKit capability가 시뮬레이터 빌드에 깨끗이 붙는지
2. Foundation Models가 개발 Mac/시뮬레이터에서 `available`로 뜨는지 (안 떠도 폴백으로 진행)

## v1 기능 범위

**코어 (포함)**

1. 습관 만들기 → 각 습관에 HealthKit 자동판정 규칙 연결 (걷기·물·수면·운동·마음챙김 등)
2. 매일 자동 체크 + 스트릭(연속 달성) 화면
3. 하루 컨디션 체크인 (기분·에너지 + 한 줄 메모)
4. 주간 AI 인사이트 ("X한 날 컨디션이 평균 N점 높음")
5. Live Activity / 잠금화면 — 사용자가 시작하는 세션(걷기/스트레칭)의 진행 링
6. 로컬 알림 (습관 리마인더)

**v2로 미룸 (멤버십 가입 후)**

- 홈 화면 데이터 위젯 (App Groups 필요)
- Apple Watch 동반 앱
- 원격 푸시 기반 Live Activity 갱신

## 데이터 모델 (SwiftData, 전부 로컬)

- **`Habit`** — 습관 정의
  - 이름, 이모지/색상, 스케줄(매일 / 특정 요일), 리마인더 시각(선택)
  - **판정 규칙(`VerificationRule`)**: HealthKit 종류 + 비교(≥ 목표 / ≤ 목표 / 특정 시각 이전) + 목표값·단위
- **`DailyResult`** — 습관 × 날짜별 결과 *(스냅샷 저장)*
  - 날짜, 상태(달성/미달/대기), **측정값**(예: 12분), 출처(자동/수동)
  - HealthKit을 매번 재조회하지 않고 하루치를 캐싱 → 스트릭·과거 기록 안정, 인사이트가 이 값을 그대로 사용
- **`ConditionEntry`** — 하루 컨디션 (하루 1개)
  - 날짜, 기분(1–5), 에너지(1–5), 한 줄 메모(선택)
- **`InsightSnapshot`** — 최근 주간 인사이트 캐시 (계산 결과 + AI가 쓴 문장 + 생성 시각)

## 화면 / 네비게이션 — 3탭

1. **오늘** (홈)
   - 상단: 컨디션 체크인 카드 (탭 → 기분·에너지 5단계 + 메모)
   - 오늘의 습관 리스트 — 자동판정 상태 + 측정값 + 스트릭 배지
     - 상태 3종: **달성**(체크) · **진행 중**(%) · **대기**(미래 조건, 예: 취침)
   - 우상단 `+` → 습관 추가 시트
   - 하단: 인사이트 티저 (탭 → 인사이트 탭)
2. **인사이트**
   - 주간 AI 요약 카드
   - 차트: 컨디션 추세 · 습관별 달성률 · 습관↔컨디션 상관 (Swift Charts)
3. **설정**
   - HealthKit 권한 상태/요청, 알림 기본값, 앱 정보
   - 홈 위젯은 "가입 후 추가" 안내 자리

**주요 시트 2개**

- **습관 추가/편집**: 이름·이모지 → 판정 종류 → 목표값 → 스케줄 → 리마인더
- **컨디션 체크인**: 기분/에너지 스케일 + 메모

## AI 인사이트 엔진

4단계 파이프라인. **숫자는 전부 Swift가 계산, 모델은 문장만 표현.**

1. **집계 (결정적)** — 최근 14~28일에서 습관별 달성률·스트릭 계산.
   상관: 각 습관을 "달성한 날 vs 안 한 날"로 나눠 평균 기분·에너지 차이(Δ) 계산.
2. **선별 (결정적)** — |Δ|와 표본 수로 순위 → 상위 1~3개.
   **최소 표본 게이트**(양쪽 각 3일 이상) 미달 시 "데이터가 더 필요해요"로 숨김 → 노이즈 차단.
3. **표현 (Foundation Models 또는 폴백)** — 구조화된 사실
   `{habit, metric, delta, direction, sampleSize}`을 모델에 전달, "숫자 바꾸지 말고
   친근한 한 문장으로" 요청. 모델 미가용 시 `TemplatePhraser`로 결정적 문구 생성.
   **숫자는 항상 1단계에서 오며, 모델은 절대 숫자를 만들지 않는다.**
4. **캐시** — `InsightSnapshot`에 저장. 하루 1회 또는 당겨서 새로고침 시 재계산.

**가드레일**

- "~한 날 컨디션이 높았어요" 같은 **관찰**로만 표현. 인과·의학적 조언 금지.
- 최소 표본 게이트로 통계적 노이즈 차단.

## 아키텍처 — 모듈 경계 (프로토콜 격리)

핵심 원칙: 각 유닛은 단일 목적 + 잘 정의된 인터페이스 + 독립 테스트 가능.
프로토콜 격리로 **시뮬/실기기/멤버십/모델 유무 차이를 구현체 교체로 흡수**한다.

- **`HealthDataSource`** *(프로토콜)* — HealthKit 추상화
  - 구현: `HealthKitDataSource`(실제) / `MockHealthDataSource`(테스트·프리뷰·데이터 없는 시뮬)
  - → 시뮬레이터/실기기, 멤버십 전후 차이를 흡수하는 핵심 seam
- **`HabitEvaluator`** — 순수 로직: 규칙 + 측정값 → DailyResult 상태. 프레임워크 의존 0
- **`InsightEngine`** — 순수 통계: DailyResult + ConditionEntry → 구조화 인사이트. 프레임워크 의존 0
- **`InsightPhraser`** *(프로토콜)* — 인사이트 → 문장
  - 구현: `FoundationModelsPhraser` / `TemplatePhraser`(폴백). 가용성 체크로 자동 선택
- **`Store`** *(SwiftData)* — 영속화(Habit, DailyResult, ConditionEntry, InsightSnapshot)
- **`RefreshService`** — 오케스트레이션: 앱 포그라운드/수동 새로고침 시
  HealthKit 조회 → 평가 → DailyResult 저장 → 인사이트 재계산
  - (무료 계정은 백그라운드 갱신 제약 → 포그라운드 구동 중심)
- **SwiftUI Views** — Store를 관찰

순수 로직 코어(`HabitEvaluator`, `InsightEngine`)는 의존성이 없어 단위테스트로 높은
신뢰도를 얻고, 프레임워크 접점(`HealthKitDataSource`, `FoundationModelsPhraser`)은
프로토콜 뒤 얇은 어댑터로 모킹 가능하다.

---

## 에러 처리

- **HealthKit 권한 거부/제한** → 앱이 죽지 않고 **수동 체크 폴백** 모드(`DailyResult.source = manual`) + 권한 안내 표시
- **HealthKit 쿼리 실패** → 해당 날짜는 "대기/알수없음" 처리, 크래시 없음, 로깅
- **Foundation Models 미가용/에러** → `TemplatePhraser`로 자동 폴백, UI 차단 없음
- **데이터 부족 / 최소 표본 미달** → 에러가 아닌 친근한 빈 상태(empty state)

---

## 테스트 전략 (TDD)

- **`HabitEvaluator`** — 규칙별(≥ / ≤ / 특정 시각 이전) + 경계값 단위테스트
- **`InsightEngine`** — Δ 계산 · 최소 표본 게이트 · 순위 단위테스트
- **`RefreshService`** — `MockHealthDataSource`로 통합 테스트
- **UI** — SwiftUI 프리뷰(목 Store 주입)로 화면 상태 점검
- 순수 로직 테스트를 먼저 작성(TDD)한 뒤 구현

## 빌드 / 툴링

- **프로젝트 생성:** XcodeGen — `project.yml` 하나로 타깃·capability·entitlements·Info.plist 선언적 관리 (git 친화적)
  - 사전 준비: `brew install xcodegen`
- **빌드:** `xcodebuild`로 시뮬레이터 빌드
- **실행/검증:** `xcrun simctl`로 시뮬레이터 부팅 · 앱 설치 · 실행 · 스크린샷
- **반복 루프:** 코드 작성 → 빌드 → 에러 수정 → 재빌드 (에이전트 주도)
- Xcode는 열어두면 디스크 변경을 실시간 반영 (시각 확인용)

## 열린 질문 / 후속

- 시뮬레이터에서 Foundation Models 가용성 — 미가용 시 폴백으로 진행(차단 아님)
- Live Activity 세션 대상 습관 종류 범위 — 구현 단계에서 1종으로 시작해 확장
- 정확한 인사이트 윈도우(14일 vs 28일) — 구현 중 데이터로 튜닝
