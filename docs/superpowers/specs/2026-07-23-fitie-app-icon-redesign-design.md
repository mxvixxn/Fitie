# Fitie 앱 아이콘 리디자인 — 설계 문서 (Design Spec)

- **날짜:** 2026-07-23
- **범위:** 앱 아이콘 교체 (에셋 + 생성 스크립트), Liquid Glass 대응 트랙 명시
- **상태:** 설계 승인됨 → 구현 계획(plan) 작성 예정

---

## 배경 / 문제

현재 앱 아이콘은 인디고 대각 그라디언트 배경에 **흰색 원(링) + 체크마크**다
(`scripts/gen_icon.py`가 생성). 문제는 "체크마크-인-서클"이 거의 모든 할일/습관 앱이
쓰는 범용 클리셰라, Fitie의 진짜 차별점(HealthKit 자동판정 기반의 건강·컨디션 앱)이
전혀 드러나지 않는다는 점이다. 결과적으로 홈 화면에서 기억에 남지 않고 "구려" 보인다.

## 목표

- 앱의 정체성(건강 데이터 기반)을 직관적으로 드러내는 아이콘으로 교체
- Apple 생태계에서 자연스럽고 프리미엄하게 읽히는 비주얼
- **iOS 26 Liquid Glass**로 확장 가능한 구조 (레이어 분리 가능)

## 비목표

- 인앱 `BrandMark`(온보딩 등 단일 완료 링) 변경 — 이번 범위 밖 (아래 "열린 항목" 참고)
- 새 브랜드 컬러 시스템 도입 — 기존 인디고 계열을 그대로 확장
- App Store 스크린샷·마케팅 에셋 일괄 갱신 — 아이콘만

---

## 컨셉

**다컬러 액티비티 링** (Apple Fitness 계보). 기존 체크마크를 버리고, 브랜드 인디고
패밀리(인디고 → 바이올렛 → 마젠타)의 동심원 링으로 "건강·활력·달성"을 상징한다.
같은 시각 언어가 앱의 핵심(HealthKit 자동판정)과 직접 연결된다.

## 정식 에셋 — "C1 클린"

승인된 후보 C1.

- **배경:** 딥 인디고 **대각 그라디언트** — top-left `#3A328A` → bottom-right `#16143C`
- **링:** 동심원 **부분 링 3개** (12시 시작, 시계방향), 둥근 캡(rounded caps)
  - 바깥 — 마젠타-핑크 `#F074C4`, sweep **306°**
  - 중간 — 바이올렛 `#A878FA`, sweep **330°**
  - 안쪽 — 인디고 `#6C74FA`, sweep **288°**
- **트랙:** 각 링 뒤에 어두운 미달성 구간(해당 링 색 × 0.42)의 전체 원 — Apple Fitness
  정통 표현이며, 부분 링의 "남은 부분"을 자연스럽게 처리
- **기하:** 링 stroke ≈ 캔버스의 9.3%, 링 간 간격 ≈ stroke × 1.34, 바깥 반지름 ≈ 33.5%
- **출력:** 1024×1024 PNG. 라운드 코너는 시스템이 처리(정사각 풀블리드로 출력)
- **안티에일리어싱:** 4× 슈퍼샘플 후 LANCZOS 다운스케일

색상값·기하 상수는 구현 시 미세 튜닝 가능하되, 위 비율을 기준으로 한다.

## 생성 방식

- **`scripts/gen_icon.py` 재작성**
  - 배경 그라디언트, 트랙 링, 부분 링(둥근 캡)을 각각 함수로 분리 → 파라미터화
  - 링 스펙(반지름·색·sweep)을 리스트로 선언해 레이어 개념을 코드에 반영
    (후속 Liquid Glass 레이어 분리와 대응)
  - 출력 경로: `Fitie/Assets.xcassets/AppIcon.appiconset/icon_1024.png` (기존 교체)
- **정적 글래스 폴백(C2):** 상단-좌측 라디얼 하이라이트 + 톱 글로스 + 림 라이트를 입힌
  변형을 **별도 파일**(예: `docs/app-icon-glass.png` 또는 스크립트 옵션)로 함께 출력.
  앱 번들에는 넣지 않으며 마케팅/미리보기 용도.
- 의존성: Pillow(PIL). 기존 스크립트와 동일.

## Liquid Glass 대응 트랙 (iOS 26, 후속)

이 프로젝트는 `deploymentTarget: iOS 26`이라 Apple의 새 아이콘 시스템을 쓸 수 있다.

- 아이콘을 **레이어로 분리**한다: (1) 인디고 그라디언트 배경, (2) 링 그룹(또는 링별 레이어)
- Apple **Icon Composer**로 `.icon` 파일을 저작하면 시스템이 실시간 **Liquid Glass**
  (반사·굴절·번짐)와 **Default/Dark/Clear/Tinted** 변형을 자동 생성
- `.icon`을 Xcode 에셋 카탈로그에 추가하고 빌드 설정을 연결
- **이 트랙은 v1 아이콘 교체를 막지 않는다.** 정적 PNG 교체를 먼저 완료하고, Liquid
  Glass는 후속 작업으로 진행. C1을 깨끗하게(정적 광택 없이) 유지하는 이유가 이것 —
  시스템 글래스와 이중으로 겹치지 않게 하기 위함.

## 검증

- 재생성 후 **180 / 120 / 60px** 축소본을 콘택트 시트로 확인 — 작은 크기에서 링 3개가
  뭉개지지 않고 구분되는지, 대비가 충분한지
- 에셋 교체 후 `xcodebuild ... build` 성공 확인
- (선택) 시뮬레이터 홈 화면에서 실제 렌더 스크린샷

## 파일 영향

- 수정: `scripts/gen_icon.py`
- 교체(생성): `Fitie/Assets.xcassets/AppIcon.appiconset/icon_1024.png`
- 추가(선택): 정적 글래스 폴백 이미지 (앱 미포함)

## 열린 항목 / 후속

- **인앱 `BrandMark`(단일 완료 링) 결 맞추기** — 이번엔 그대로 둔다. 단일 링도 "완료 링"
  의미로 충분히 일관됨. 원하면 트라이-링 반영을 별도 작업으로.
- Icon Composer 기반 `.icon` 저작 (Liquid Glass 정식 대응) — 별도 트랙.
- App Store 스크린샷/README 아이콘 이미지 갱신 — 아이콘 확정 후.
